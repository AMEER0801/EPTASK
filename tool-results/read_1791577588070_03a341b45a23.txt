    62→    94→    94→    p = Paragraph(f'<a name="{key}"/>{text}', style)

   184→   216→   216→## Step 3: EDIT - Content Transformation
   185→   217→   217→
   186→   218→   218→**Before writing any code, restructure raw text into visual roles.** This is the most impactful quality step - skipping it produces "Word document with a PDF extension".
   187→   219→   219→
   188→   220→   220→### 3a. Typographic Role Extraction
   189→   221→   221→
   190→   222→   222→Parse raw text and categorize content into visual roles:
   191→   223→   223→
   192→   224→   224→| Role | ReportLab Mapping | Description |
   193→   225→   225→|------|------------------|-------------|
   194→   226→   226→| **Hero / Display** | Cover title (36-42pt) or section opener | 1-5 words, the emotional hook |
   195→   227→   227→| **Kicker / Eyebrow** | Subtitle or section intro (10-12pt, muted) | Tiny context line above main heading |
   196→   228→   228→| **Data Sculpture** | CalloutBox or bold stat block | Extract impactful numbers (97%, $4.2M, -45ms) |
   197→   229→   229→| **Pull Quote** | BlockQuote (italic + left indent 24pt + accent border) | Most provocative sentence, standalone |
   198→   230→   230→| **Body** | Standard paragraph | Everything else |
   199→   231→   231→
   200→   232→   232→**Rule**: Before writing any body paragraph, scan for numbers with units. Every metric like "revenue grew by 12%" or "latency dropped to 45ms" MUST be extracted into a CalloutBox or metrics table - never buried in paragraph prose. See §Data-to-Ink Ratio Rules below.
   201→   233→   233→
   202→   234→   234→### 3b. Section Pacing
   203→   235→   235→
   204→   236→   236→- If any H1 section has **>400 words** of continuous body text without visual breaks, split into H2 subsections or insert a visual break (table, chart, callout)
   205→   237→   237→- Aim for at least 1 visual element (table/chart/callout) per 2-3 pages of body text
   206→   238→   238→- Dense text walls are the #1 sign of poor report design
   207→   239→   239→
   208→   240→   240→### 3c. Content Sanitization for External Sources (MANDATORY when source is PDF/OCR/web)
   209→   241→   241→
   210→   242→   242→When content is extracted from an external PDF, OCR output, or web scrape, it may contain invisible garbage characters that cause garbled rendering. **You MUST sanitize the text content before writing it into any `Paragraph()` or `canvas.drawString()`.**
   211→   243→   243→
   212→   244→   244→This is different from `code.sanitize` (which cleans Python source code). Content sanitization cleans the **text data itself**.
   213→   245→   245→
   214→   246→   246→```python
   215→   247→   247→import re
   216→   248→   248→
   217→   249→   249→def content_sanitize(text: str) -> str:
   218→   250→   250→    """Strip invisible/control chars from externally-sourced text."""
   219→   251→   251→    # Remove control chars (except \n \t)
   220→   252→   252→    text = re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]', '', text)
   221→   253→   253→    # Remove zero-width chars
   222→   254→   254→    text = re.sub(r'[\u200b-\u200f\u2028-\u202f\u2060\ufeff]', '', text)
   223→   255→   255→    # Remove replacement char (upstream encoding error)
   224→   256→   256→    text = text.replace('\ufffd', '')
   225→   257→   257→    # Remove variation selectors
   226→   258→   258→    text = re.sub(r'[\ufe00-\ufe0f]', '', text)
   227→   259→   259→    # Remove private use area chars
   228→   260→   260→    text = re.sub(r'[\ue000-\uf8ff]', '', text)
   229→   261→   261→    return text
   230→   262→   262→```
   231→   263→   263→
   232→   264→   264→**When to use:**
   233→   265→   265→| Source | Must sanitize? |
   234→   266→   266→|--------|---------------|
   235→   267→   267→| User typed text in prompt | No (usually clean) |
   236→   268→   268→| Extracted from PDF via `pdf.py extract.text` | **YES** |
   237→   269→   269→| OCR output | **YES** |
   238→   270→   270→| Web scrape / HTML strip | **YES** |
   239→   271→   271→| LLM-generated content | No (usually clean) |
   240→   272→   272→
   241→   273→   273→⚠️ **Do NOT confuse** `code.sanitize` (Step 6, cleans Python code) with `content_sanitize()` (Step 3, cleans text data). They solve different problems.

   270→   302→   302→## Character Safety Rule (MANDATORY)
   271→   303→   303→
   272→   304→   304→Three rules for safe character handling in ReportLab PDFs:
   273→   305→   305→
   274→   306→   306→**a) Superscripts and subscripts**: Use `<super>`/`<sub>` tags, never raw Unicode superscript/subscript characters (e.g., `\u00b2`, `\u2082`).
   275→   307→   307→
   276→   308→   308→**b) Emoji**: ReportLab cannot render emoji. If content contains emoji, use Creative brief (HTML + Playwright).
   277→   309→   309→
   278→   310→   310→**c) Font fallback for mixed CJK/Latin text (MANDATORY)**: After registering fonts, you **MUST** call `install_font_fallback()` once. This automatically wraps missing-glyph characters in `<font>` tags inside every `Paragraph()`. No manual `<font name="...">` wrapping needed for mixed Chinese-English text. **Skipping this call is the #1 cause of Helvetica garbled text in CJK documents.**
   279→   311→   311→
   280→   312→   312→**d) canvas.drawString / drawRightString CJK font rule (MANDATORY)**: `install_font_fallback()` only works on `Paragraph()` objects. It does NOT affect `canvas.drawString()` / `canvas.drawRightString()` / `canvas.drawCentredString()`. If the text passed to any `canvas.draw*String()` call contains CJK characters (Chinese/Japanese/Korean), you **MUST** call `canvas.setFont('NotoSerifSC', size)` (or another registered CJK font) before drawing. Using FreeSerif / Helvetica / Times for CJK canvas text = garbled output.
   281→   313→   313→
   282→   314→   314→```python
   283→   315→   315→# ❌ WRONG — FreeSerif has no CJK glyphs, '科大讯飞' will be garbled
   284→   316→   316→canvas.setFont('FreeSerif-Italic', 8)
   285→   317→   317→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   286→   318→   318→
   287→   319→   319→# ✅ CORRECT — use CJK font for mixed text
   288→   320→   320→canvas.setFont('NotoSerifSC', 8)
   289→   321→   321→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   290→   322→   322→
   291→   323→   323→# ✅ ALSO CORRECT — pure English text can use FreeSerif
   292→   324→   324→canvas.setFont('FreeSerif-Italic', 8)
   293→   325→   325→canvas.drawString(x, y, 'Prepared by Strategy Advisory Team')
   294→   326→   326→```
   295→   327→   327→
   296→   328→   328→Mathematical/relational operators (×, ÷, ±, ≤, √, ∑, ≅, ∫, π, ∠, Δ, etc.) are safe to use as literal characters in `Paragraph()` - both Noto Sans SC and FreeSerif have these glyphs.
   297→   329→   329→
   298→   330→   330→| Need | Correct Method | Correct Example |
   299→   331→   331→|------|---------------|---------|
   300→   332→   332→| Superscript | `<super>` tag in `Paragraph()` | `Paragraph('10<super>2</super> × 10<super>3</super> = 10<super>5</super>', style)` |
   301→   333→   333→| Subscript | `<sub>` tag in `Paragraph()` | `Paragraph('H<sub>2</sub>O', style)` |
   302→   334→   334→| Bold | `<b>` tag in `Paragraph()` | `Paragraph('<b>Title</b>', style)` |
   303→   335→   335→| Math operators | Literal char in `Paragraph()` | `Paragraph('AB ⊥ AC, ∠A = 90°, and ΔABC ≅ ΔDCF', style)` |
   304→   336→   336→| Scientific notation | Combined tags in `Paragraph()` | `Paragraph('1.2 × 10<super>8</super> kg/m<super>3</super>', style)` |
   305→   337→   337→
   306→   338→   338→```python
   307→   339→   339→from reportlab.platypus import Paragraph
   308→   340→   340→from reportlab.lib.styles import ParagraphStyle
   309→   341→   341→from reportlab.lib.enums import TA_LEFT, TA_CENTER, TA_JUSTIFY
   310→   342→   342→
   311→   343→   343→body_style = ParagraphStyle(
   312→   344→   344→    name="ENBodyStyle",
   313→   345→   345→    fontName="FreeSerif",
   314→   346→   346→    fontSize=10.5,
   315→   347→   347→    leading=18,
   316→   348→   348→    alignment=TA_JUSTIFY,
   317→   349→   349→)
   318→   350→   350→
   319→   351→   351→# CJK Body (Chinese documents)
   320→   352→   352→cn_body_style = ParagraphStyle(
   321→   353→   353→    name="CNBodyStyle",
   322→   354→   354→    fontName="NotoSerifSC", fontSize=10.5, leading=18,
   323→   355→   355→    alignment=TA_LEFT,      # ← NEVER TA_JUSTIFY for CJK
   324→   356→   356→    wordWrap='CJK',         # ← MANDATORY for CJK
   325→   357→   357→    firstLineIndent=2*4.5*mm,
   326→   358→   358→)
   327→   359→   359→
   328→   360→   360→# Superscript: area unit
   329→   361→   361→Paragraph('Total area: 500 m<super>2</super>', body_style)
   330→   362→   362→
   331→   363→   363→# Subscript: chemical formula
   332→   364→   364→Paragraph('The reaction produces CO<sub>2</sub> and H<sub>2</sub>O', body_style)
   333→   365→   365→
   334→   366→   366→# Scientific notation
   335→   367→   367→Paragraph('Speed of light: 3.0 × 10<super>8</super> m/s', body_style)
   336→   368→   368→
   337→   369→   369→# Combined
   338→   370→   370→Paragraph('E<sub>k</sub> = mv<super>2</super>/2', body_style)
   339→   371→   371→
   340→   372→   372→# Bold heading
   341→   373→   373→Paragraph('<b>Chapter 1: Introduction</b>', header_style)
   342→   374→   374→
   343→   375→   375→# Math symbols
   344→   376→   376→Paragraph('When ∠ A = 90°, AB ⊥ AC and ΔABC ≅ ΔDEF', body_style)
   345→   377→   377→```
   346→   378→   378→
   347→   379→   379→**Pre-generation check - before writing ANY string, ask:**
   348→   380→   380→> "Does this string contain a character outside basic CJK or Mathematical/relational operators?"
   349→   381→   381→> If YES → it MUST be inside a `Paragraph()` with the appropriate tag.
   350→   382→   382→> If it is a superscript/subscript digit in raw unicode escape form → REPLACE with `<super>`/`<sub>` tag.
   351→   383→   383→
   352→   384→   384→**NEVER rely on post-generation scanning. Prevent at the point of writing.**
   353→   385→   385→
   354→   386→   386→**Encoding safety - before writing ANY content text:**
   355→   387→   387→> "Does this string contain Japanese kana (の, が, は etc.) or rare Unicode symbols?"
   356→   388→   388→> If YES → REPLACE with safe plain Chinese equivalents. Japanese kana (Hiragana U+3040-U+309F, Katakana U+30A0-U+30FF) frequently corrupt to U+FFFD (�) when code passes through LLM output, heredoc, or terminal encoding layers.
   357→   389→   389→> Common safe replacements: `活の真鲷`→`活缔真鲷`, `盐烤の鲭鱼`→`盐烤鲭鱼`, `烤の鸡串`→`炭烤鸡串`.
   358→   390→   390→> If the character is genuinely needed, verify it survives a full write→read round-trip with `open(file, encoding='utf-8')`.

   423→   455→   455→
   424→   456→   456→**For Chinese PDFs:**
   425→   457→   457→- Body text: `NotoSerifSC` (primary) — serif font with sharp, elegant strokes
   426→   458→   458→- Headings: `NotoSerifSC-Bold` (MUST use for Chinese headings) — same family, bolder weight for clear hierarchy

   434→   466→   466→- Headings: `FreeSerif` (MUST use for English headings)

   437→   469→   469→
   438→   470→   470→**For Mixed Chinese-English PDFs:**
   439→   471→   471→- Call `install_font_fallback()` once after registering fonts - it automatically wraps characters in `<font>` tags so you don't need to do it manually.
   440→   472→   472→- If you still want manual control, you can use `<font name='...'>` tags, but the automatic fallback handles most cases.
   441→   473→   473→

   443→   475→   475→import sys, os
   444→   476→   476→sys.path.insert(0, os.path.join(os.path.dirname(__file__), 'scripts'))
   445→   477→   477→from pdf import install_font_fallback
   446→   478→   478→
   447→   479→   479→# 1. Register fonts (as above)
   448→   480→   480→# 2. Install fallback - one line, handles all mixed-language text
   449→   481→   481→install_font_fallback()
   450→   482→   482→
   451→   483→   483→# 3. Just write naturally - no manual <font> wrapping needed!
   452→   484→   484→en_style = ParagraphStyle(name="EN", fontName="FreeSerif", fontSize=10.5, leading=18)
   453→   485→   485→cn_style = ParagraphStyle(name="CN", fontName="NotoSerifSC", fontSize=10.5, leading=18, wordWrap='CJK')
   454→   486→   486→
   455→   487→   487→Paragraph('MySQL、PostgreSQL、Redis', en_style)           # ✅ CJK comma auto-fallback to NotoSerifSC
   456→   488→   488→Paragraph('Beijing (北京) has 21M people', en_style)       # ✅ CJK chars auto-fallback
   457→   489→   489→Paragraph('价格:¥2,200~5,800/月', en_style)               # ✅ all CJK chars handled
   458→   490→   490→Paragraph('《巴黎协定》签署于2015年', en_style)               # ✅ CJK book title marks handled
   459→   491→   491→```
   460→   492→   492→
   461→   493→   493→**How it works:** `install_font_fallback()` monkey-patches `Paragraph.__init__` to scan each character against the font's `charToGlyph` table. Characters missing from the base font are automatically wrapped in `<font name="FallbackFont">`. The fallback chain is: English fonts → NotoSerifSC (primary) or Noto Sans SC (legacy), Chinese fonts → FreeSerif. For aesthetic optimization, Cyrillic text in NotoSerifSC/Noto Sans SC is automatically routed to FreeSerif (serif looks better for Cyrillic).
